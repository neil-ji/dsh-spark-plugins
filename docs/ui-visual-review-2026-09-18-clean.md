## 7. 遗留与方法学建议

1. **本轮复核对的是沙箱宿主（3997），不是常驻 3080。** 原因：3080 是当前会话所在的服务，
   重启它会中断会话；沙箱宿主走的是**同一条 tarball 保真安装路径**，且版本可证明等于仓库源码。
   要把 3080 也刷新到同一批产物，命令是
   `node scripts/install-profile.mjs web --no-build`（home 默认 `~/.dsh`）→ **重启 `dsh web`**（重启必须由用户决定）。
2. **数据面差异**：沙箱数据是测试记忆/火花，**财务缺订阅计划与模型行** → PCQA-008/009/010/018 只能在真数据上做视觉确认
   （其中 009/010 已从源码层判定为已修）。
3. **建议加一条验收前防线**（可入 `dev-harness/real-host-check.mjs` 或 PC-QA 流程首步）：
   断言「宿主实际加载的插件版本 == 仓库版本」+「注入样式块内 `--dsw-alias-*` 计数 == 0」+「卡片题 == 14px」。
   这三条本轮各只用了 1 次 CDP 求值，却能一次性拦住本次这类**整轮假阳性**。
4. **术语**：原报告标题里的 `PCQA-*` 编号与 `docs/ui-acceptance-2026-09-17.md` 里的 `PCQA-*` **重号但不指同一件事**
   （轮次从 001 重新编号），引用时必须带轮次号，否则会造成「PCQA-007 已修/未修」的对不上账。
